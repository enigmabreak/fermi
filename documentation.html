Fermi Studio Documentation

More details at enigmabreak.github.io/fermi

Welcome to Fermi Studio, the secure coding environment designed for academic integrity.

For Students: How to Use the Application

  • Workspace Configuration: Upon launch, you must enter your 11-digit University Roll Number. This initializes your secure session and locks the IDE to fullscreen.
  • Saving Work: Your C files are automatically saved to your secure workspace folder. To compile and run, click the Run button or press Ctrl+Enter.
  • Compilation Errors: The IDE uses an ultra-fast C compiler that parses code line-by-line. If your code has a fatal syntax error, the compiler will stop and report only that single error. Fix it and re-run to see any subsequent errors.
  • External Files: If you open a C file that was not created in this session, the editor will flag it with a reddish tab border and log the event as a high-risk violation.
  • Focus Tracking: Do not minimize the window or switch to other applications. The IDE actively tracks foreground application changes in real-time, identifying the exact external application accessed.
  • USB Lockdown: Do not insert USB drives during a session. Doing so will forcefully restore the IDE to fullscreen and immediately lock the screen until the exact device is removed. The incident is rigorously logged with timestamps and device name.
  • Paste Restrictions: Pasting code is strictly prohibited. The first attempt shows a warning; subsequent attempts are logged as violations.
  • Close Attempts: Attempting to close the IDE during a session via the title bar or keyboard shortcut will show a warning dialog instead of closing, and the attempt is logged.
  • Automatic Workspace Cleanup: To free up lab PC storage, student source code folders are automatically deleted 6 hours after they were first created. This runs silently at application startup.

For Students: Exporting Your Report

  • You may export your current Integrity Report mid-session via File → Export Integrity Report.
  • Reports exported this way are permanently marked with a red "Incomplete Report (?)" banner at the top. This informs the examiner that the session had not yet ended at the time of export and that further activity may have occurred afterwards.
  • The final, official report is the one automatically generated when the application closes at the end of your session. That report has no such banner and is what the examiner will use for evaluation. You do not need to manually export it.

For Students: Practice Mode

If you want to practice coding in an unrestricted environment without triggering security violations, you can use Practice Mode.

  • Activation: Type practice into the Roll Number field during startup.
  • Capabilities: Practice Mode operates similarly to Admin Mode—it allows you to freely switch windows, copy and paste, and browse the entire file system without logging violations or locking you in fullscreen.
  • Environment: The interface adopts a distinct deep green theme, and the session clock remains active so you can track your practice time.
  • USB Lockdown: Unlike Admin mode, inserting a USB drive in Practice Mode will still trigger the security lockdown.
  • Automatic Cleanup: To ensure lab computers don't run out of storage, any files saved in your practice workspace folder that are older than 3 hours are automatically wiped upon starting a new Practice Mode session.

For Professors: Supermode (Admin Mode)

To assist students or review reports without triggering integrity violations, invigilators can use the built-in Supermode.

  • Activation: Type admin into the Roll Number field during startup.
  • Capabilities: Supermode automatically bypasses all paste restrictions, disables window-switch monitoring, completely ignores USB insertions, exits fullscreen, disables automatic workspace cleanup, and suppresses Integrity Report generation for the session.
  • Admin Panel: Entering Supermode automatically opens the Admin Panel, where you can view and browse all saved student Integrity Reports. The panel can also be opened at any time via File → Reports.
  • Stealth: No events are recorded for the admin session, keeping logs clean.

For Professors: Admin Panel — Identifying Incomplete Reports

The Admin Panel lists all reports by student roll number and the timestamp they were generated. When reviewing a report, pay attention to the following:

  • A report marked "Incomplete Report (?)" with a red banner at the top was manually exported by the student while their session was still active. It does not represent the full picture of their session.
  • Always prefer the final auto-generated report for evaluation. It is created automatically when the student closes the application and captures the complete session without any banner.
  • Mid-session exports may be used as supplementary evidence but should never be treated as the final record.

For Professors: Integrity Report Contents

Each Integrity Report is a self-contained HTML document containing the following information:

  • Session Start and Report Time — Timestamps in 12-hour AM/PM format.
  • Total Activity Period — The elapsed time from session start to when the report was generated.
  • Focus Lost Duration — Total time the student had the IDE out of focus.
  • Window Switches, Paste Attempts, USB Insertions, External Files — Counts of each violation type.
  • USB Active Time — Cumulative time any USB device was connected during the session.
  • Risk Score and Risk Level — A calculated score (CLEAN, MEDIUM, or HIGH) summarizing the severity of the session.
  • Time on Individual Programs — A table showing coding time and execution time per .c file worked on.
  • Detailed Event Tables — Timestamped records of USB events, external files opened, window switches, paste attempts, and session-close events.

All reports follow the unified naming format:

IR_<roll>_<yyyy-mm-dd>_<hh-mm-ss><AM/PM>.html

For Professors: Scoring & Risk Levels

Fermi Studio operates a deterministic risk scoring model. The system starts every session with a base Trust Score of 100. Penalty points are deducted for various violations. The score can drop below zero for severe or repeated infractions.

Automatic Data Management

Fermi Studio automatically manages stored data at every startup to keep lab PCs clean:

  • Workspace Folders: Student source code folders older than 6 hours from their creation time are permanently deleted at startup.
  • Integrity Reports: Reports older than 30 days from their creation date are permanently deleted at startup.
